## ۸-۱ | کاربر، گروه و ریشه

لینوکس از لحظه راه‌اندازی، یک کاربر ویژه به نام **root** دارد: مدیر کل سیستم که به همه‌جا اجازه ورود دارد. کاربر معمولی شما (که موقع نصب ساختید) عمداً قدرت محدودی دارد و وقتی کار مدیریتی لازم شد، با دستور `sudo` همان یک دستور را با قدرت root اجرا می‌کند. این جدایی عمدی، بزرگ‌ترین دلیل امنیت لینوکس است: ویروس یا اشتباهِ روزمره، فقط به اندازه دسترسی شما می‌تواند خرابکاری کند.

هر کاربر می‌تواند عضو چند **گروه** باشد — گروه‌ها روش تمیزی برای دادن دسترسی جمعی‌اند (مثلاً گروه `sudo` یعنی «اجازه sudo دارد»؛ گروه `docker` یعنی «بدون sudo با داکر کار کند» — فصل ۱۳ می‌بینیدش):

::: term
$ whoami                 # من کی‌ام؟
$ id                     # شناسه من + گروه‌هایم
$ sudo adduser ali       # ساخت کاربر جدید (سؤال‌به‌سؤال رمز می‌گیرد)
$ groups ali             # گروه‌های ali
$ sudo usermod -aG sudo ali   # ali را عضو گروه sudo کن (دسترسی مدیر)
:::

## ۸-۲ | خواندن مجوزها؛ آن رشته رمزآلود `rwxr-xr--`

یادتان هست در `ls -l` اول هر خط چنین چیزی دیدیم؟ حالا رمزگشایی می‌کنیم:

::: figure inline:perms | شکل ۸-۱: کالبدشکافی مجوزها؛ سه گروه سه‌حرفی و معادل عددی ۷۵۴ | 330
:::

سه سه‌تایی به ترتیب یعنی: مجوزِ **مالکار (u)**، مجوزِ **گروه (g)** و مجوزِ **بقیه (o)**. و هر سه‌تایی سه حرف دارد: **r** خواندن، **w** نوشتن، **x** اجرا. پس `rw-r--r--` یعنی: مالکار می‌خواند و می‌نویسد؛ گروه فقط می‌خواند؛ بقیه فقط می‌خوانند. برای پوشه‌ها، `x` معنی «اجازه ورود» می‌دهد — به همین دلیل پوشه‌ها تقریباً همیشه x دارند.

هر مجوز یک عدد هم دارد: r=4، w=2، x=1 — جمع سه‌تایی، یک رقم می‌شود: `rwx`=7، `r-x`=5، `r--`=4. به همین ترتیب `754` یعنی همان `rwxr-xr--`. این «مجوز عددی» زبان مشترک همه‌ی آموزش‌های اینترنتی است و از این به بعد برای شما رمز نیست.

## ۸-۳ | chmod و chown؛ تغییر قفل‌ها

::: term
$ chmod +x backup.sh            # اجرایی کن (رایج‌ترین chmod دنیا!)
$ chmod 644 report.pdf          # مالکار: خواندن+نوشتن، بقیه: فقط خواندن
$ chmod 700 ~/secret            # فقط خودم؛ حتی بقیه خواندن هم نداشته باشند
$ chmod -R 755 ~/website        # بازگشتی روی کل پوشه
$ sudo chown ali:ali /srv/app   # مالک و گروه را به ali بده
:::

سه مجوز کلاسیک که در همه‌جای وب می‌بینید و باید حفظ باشید: **۶۴۴** برای فایل‌های معمولی، **۷۵۵** برای پوشه‌ها و اسکریپت‌ها/برنامه‌ها، **۶۰۰** برای فایل‌های محرمانه فقط برای خودتان (مثل کلید ssh در فصل ۱۱). و `chmod 777` (همه‌کارهای همه) تقریباً همیشه یک اشتباه امنیتی است — اگر راه‌حلی از اینترنت گفت «بزن ۷۷۷»، آن راه‌حل را دور بریزید.

::: story | ماجرای chmod 777
روی یک سرور وب، اپلیکیشنی اجازه نوشتن نداشت و مسئول سرور برای «درست شدن» اجرا کرد: `chmod -R 777 /var/www`. مشکل فوری حل شد؛ اما حالا هر کاربری از هر مسیری می‌توانست فایل‌های سایت را بازنویسی کند. دو ماه بعد، سایت هک شد و فایل‌های مخرب جای صفحات نشست. درس: مجوز را «درست» بدهید نه «باز». اشکال را در مالکیت (chown) و گروه‌ها جست‌وجو کنید، نه در باز کردن همه درها.
:::

## ۸-۴ | عادات امنیتی پایه؛ از امروز

1. **روزمره با کاربر معمولی؛ sudo فقط در حد نیاز.** هرگز لاگین روزمره با root نداشته باشید.
2. **آپدیت منظم:** `sudo apt update && sudo apt upgrade` هفتگی — بیشتر حملات از حفره‌های «کهنه» می‌آیند.
3. **رمز مدیر قوی و یکتا** — و یادتان باشد رمز در ترمینال دیده نمی‌شود؛ طبیعی است.
4. **مجوز فایل‌های محرمانه را ببندید** (`chmod 600`) و در فایل‌های اشتراکی حساس باشید.
5. **قبل از هر sudo در اینترنت‌خوانده، بفهمید چه می‌کند** — sudo یعنی «حالا می‌توانم اشتباه بزرگ کنم».

::: exercise | تمرین فصل ۸
(۱) با `ls -l` مجوزهای فایل‌های پوشه خانه را رمزگشایی کنید و سه فایل با سه الگوی متفاوت پیدا کنید. (۲) فایلی بسازید، `chmod 600` بدهید و با کاربر دیگری (یا `sudo cat`) امتحان کنید که خواندنش ممکن نیست. (۳) اسکریپت `hello.sh` فصل ۷ را با `chmod +x` اجرایی کنید و این بار مستقیم با `./hello.sh` اجرایش کنید. (۴) `id` بگیرید و ببینید عضو کدام گروه‌های ویژه‌اید.
:::

::: key | جمع‌بندی فصل ۸
- root همه‌قدت‌دار است؛ کاربر معمولی + sudo = امنیت با آگاهی. گروه‌ها دسترسی جمعی می‌دهند.
- rwx برای مالکار/گروه/بقیه؛ اعداد: r=4، w=2، x=1 — ۶۴۴ فایل، ۷۵۵ پوشه/اسکریپت، ۶۰۰ محرمانه.
- `chmod +x` اجرا می‌کند؛ `chown` مالکیت را می‌دهد؛ ۷۷۷ تقریباً همیشه یک اشتباه است.
- امنیت پایه: آپدیت هفتگی، رمز قوی، sudo محدود و آگاهانه.
:::
