## ۷-۱ | خواندن؛ هر فایل به اندازه نیاز شما

چهار ابزار خواندن داریم و هر یک برای موقعیتی خاص بهترین است:

::: term
$ cat /etc/os-release        # کل فایل، یکجا (برای فایل‌های کوتاه)
$ less /var/log/syslog       # صفحه‌به‌صفحه؛ فلش‌ها، / جستجو، q خروج
$ head -20 notes.txt         # فقط ۲۰ خط اول
$ tail -20 /var/log/syslog   # فقط ۲۰ خط آخر
$ tail -f /var/log/syslog    # دنبال کردن زنده! (با Ctrl+C قطع کنید)
:::

ستاره این فهرست `less` است: با فایل‌های بزرگ مثل لاگ‌های چندمگابایتی، `cat` صفحه را شلوغ می‌کند اما `less` مثل یک خواننده حرفه‌ای رفتار می‌کند: می‌برید، جست‌وجو می‌کنید (با `/کلمه`) و می‌روید. و `tail -f` جادوی واقعی است: فایل را «زنده» دنبال می‌کند — هر خط جدیدی که لاگ بنویسد، همان لحظه جلوی چشم شماست. هر توسعه‌دهنده‌ای روزی ده بار از آن استفاده می‌کند.

::: tip | لاگ‌های اوبونتوی ۲۶.۰۴
در سیستم‌های مدرن لاگ‌ها به systemd می‌روند و با `journalctl` خوانده می‌شوند (فصل ۱۰). اما فایل‌های `/var/log` هنوز سر جای خودشان‌اند: `syslog` رویدادهای عمومی، `auth.log` ورودها و دسترسی‌ها. برای جست‌وجوی سریعِ هر دو دنیا: `journalctl -e` آخرِ لاگ سیستم را نشان می‌دهد.
:::

## ۷-۲ | grep؛ سگ شکاری متن

`grep` در دل هزاران خط، هر چیزی را که بگویید پیدا می‌کند. الگوی آن: `grep [گزینه‌ها] الگو [فایل]`:

::: term
$ grep "error" app.log            # خط‌های حاوی error
$ grep -i "error" app.log         # بزرگ/کوچکی حروف مهم نیست
$ grep -n "TODO" main.py          # با شماره خط
$ grep -r "192.168" /etc/         # جستجوی بازگشتی در کل پوشه
$ grep -v "debug" app.log         # برعکس: بدون خط‌های debug
$ grep -c "fail" app.log          # فقط بشمار
:::

و قدرت واقعی وقتی است که grep را با **لوله (pipe)** — علامت `|` — به دستورهای دیگر وصل کنید: خروجی یک دستور می‌شود ورودی دستور بعدی:

::: term
$ ls -lh | grep -i pdf           # فقط خط‌های pdf از خروجی ls
$ history | grep apt             # از تاریخچه، فقط دستورهای apt
$ grep -r " Persist" /var/log/syslog | wc -l
:::

آن `| wc -l` یعنی «بشمار چند خط شد» — همین ترکیب ساده، کوچک‌ترین ابزار آماری دنیاست. لوله‌کشی مفهومی بنیادی است؛ در فصل ۱۲ داخل اسکریپت‌ها از آن استفاده‌های جدی می‌کنیم.

## ۷-۳ | nano؛ ویرایشگر دوست‌داشتنی شروع

`nano` ساده‌ترین ویرایشگر متنِ درون‌ترمینالی است و روی همه سرورها هست — وقتی از راه دور به سرور وصلید (فصل ۱۱)، نجات‌بخش شماست:

::: term
$ nano ~/notes.txt
:::

باز شد! تایپ کنید مثل هر ویرایشگری. پایین صفحه راهنمای کلیدهاست که علامت `^` یعنی Ctrl: **Ctrl+O** ذخیره (سپس Enter برای تأیید نام)، **Ctrl+X** خروج، **Ctrl+K** بریدن خط، **Ctrl+W** جست‌وجو. همین چهار تا ۹۰٪ نیاز شماست. تمرین کلاسیک: یک اسکریپت کوچک بسازید و اجرایش کنید — اولین برخورد شما با فصل ۱۲:

::: term
$ nano hello.sh
# داخل فایل بنویسید:  echo "Hello, Linux!"
$ bash hello.sh
Hello, Linux!
:::

## ۷-۴ | vim و VS Code؛ دو دنیا، یک هدف

روی سرورهای واقعی گاهی فقط vim هست، پس حداقلش را بدانید: `vim file` باز می‌کند در «حالت عادی» (تایپ نمی‌شود!). با **i** وارد حالت درج شوید و تایپ کنید؛ با **Esc** برگردید؛ **:wq** ذخیره و خروج، **:q!** خروج بدون ذخیره. همین چهار کلید، بدترین موقعیت‌ها را نجات می‌دهد — بقیه‌ی vim ماجرایی است برای کنجکاوها.

اما راحت‌ترین راه برنامه‌نویسی در لینوکس: **VS Code**. نصبش کنید (فایل .deb یا از App Center) و بعد در هر پوشه‌ای `code .` بزنید — کل پروژه با ترمینال یکپارچه باز می‌شود. ترکیب «ترمینال + VS Code» استاندارد طلایی توسعه‌دهنده‌های لینوکسی است.

::: exercise | تمرین فصل ۷
(۱) با nano فایل `~/shopping.txt` بسازید و پنج قلم خرید بنویسید و ذخیره کنید. (۲) با `grep -n` قلم سوم را پیدا کنید. (۳) با `cat` و لوله به `wc -l` تعداد اقلام را بشمارید. (۴) `journalctl -e` را اجرا کنید و سه خط آخرِ رویدادهای سیستم را در دفترتان بنویسید. (۵) اگر VS Code دارید، در همان پوشه `code .` بزنید و فایل را همان‌جا هم ببینید.
:::

::: key | جمع‌بندی فصل ۷
- کوتاه: cat؛ بلند و قابل جست‌وجو: less؛ انتها: head/tail؛ زنده: tail -f (لاگ‌های مدرن: journalctl).
- grep با -i و -n و -r و -v متن را کالبدشکافی می‌کند؛ `|` خروجی را به دستور بعدی می‌ریزد.
- nano با Ctrl+O/Ctrl+X ویرایش روزمره؛ vim حداقلی (i، Esc، :wq) ناجی سرورهاست.
- ترکیب ترمینال + VS Code (`code .`) استاندارد کار حرفه‌ای است.
:::
